% ------------------------------------------------------------
% Balken-Bindung: ein Titelbalken steht nie allein am Spaltenfuss
% ------------------------------------------------------------
% Ein Balken ohne den Anfang seines Inhalts ist der auffälligste Layoutfehler
% einer ZSF: Man sieht die Überschrift, aber nicht, wozu sie gehört.
%
% Die frühere Platzreserve allein hat das nicht verhindert, sondern verursacht.
% Sie besteht aus \penalty0 … \penalty-100 und legt damit einen BILLIGEN
% Umbruchpunkt an genau die Stelle, an der ein Balken gerade fertig gesetzt
% wurde. Die zugehörige Bremse — Stretch-Glue, die einen Umbruch bei viel
% Restplatz unattraktiv macht — trägt unter \raggedcolumns nicht mehr, weil
% multicols den Spaltenboden ohnehin frei auffüllt. Übrig blieb die Einladung
% zum Umbruch. Genau dort brach die Spalte.
%
% Deshalb zwei getrennte Aufgaben statt einer:
%   \ZSFReserveSpace  — „lieber vorher umbrechen, wenn es eng wird" (Bremse)
%   \ZSFTitleBarLock  — „hier NICHT umbrechen, es kam noch kein Inhalt" (Sperre)
% Die Sperre ist die verlässliche; sie hängt an keiner Höhenschätzung.
\newif\ifzsfTitleBarPending
\newcommand{\ZSFTitleBarLockOn}{\global\zsfTitleBarPendingtrue}
\newcommand{\ZSFTitleBarLockOff}{\global\zsfTitleBarPendingfalse}

% Jeder Umbruchpunkt, den das Balken-System selbst setzt, läuft hierüber:
% solange noch kein Inhalt folgte, wird daraus ein Verbot.
\newcommand{\ZSFBarPenalty}[1]{%
  \ifzsfTitleBarPending\penalty10000\else\penalty#1\fi
}

% Platzreserve vor einem Titelbalken: Ist weniger als #1 frei, bricht die
% Spalte davor um. Genau eine Implementierung — die drei Balkenebenen
% unterscheiden sich nur im Schwellwert (rules/30_spacing).
% Direkt hinter einem Balken entfällt sie zugunsten der Sperre.
\newcommand{\ZSFReserveSpace}[1]{%
  \par
  \ifzsfTitleBarPending
    \penalty10000
  \else
    \penalty0\vspace{0pt plus #1}\penalty-100\vspace{0pt plus -#1}%
  \fi
  \relax
}
\newcommand{\BreakIfNotEnoughSpace}{\ZSFReserveSpace{\ZSFbreakThreshold}}
\newcommand{\BreakIfNotEnoughSpaceChapter}{\ZSFReserveSpace{\ZSFbreakThresholdChapter}}
\newcommand{\BreakIfNotEnoughSpaceSubsubsection}{\ZSFReserveSpace{\ZSFbreakThresholdSubsubsection}}

% Einheitlicher Top-Spacing-Kontrakt für Titelbalken.
% Reihenfolge ist kritisch: \addvspace MUSS vor \BreakIfNotEnoughSpace stehen,
% damit es per Max-Semantik mit dem after-skip der Vorbox kollabiert.
% tcolorbox-Definitionen, die diesen Helper rufen, MUESSEN before skip=0pt
% setzen, damit das Spacing nicht doppelt eingerechnet wird.
\newcommand{\ZSFTitleBarTopSpacing}[1]{%
  \par
  \addvspace{#1}%
  \BreakIfNotEnoughSpace
}

% ------------------------------------------------------------
% Titelbalken — gemeinsame Basis
% ------------------------------------------------------------
% Alle vier Balken (Kapitel, Dokumenttitel, Abschnitt, Unterabschnitt) teilen
% denselben Rahmenlos-Kontrakt. Sie setzen nur noch, worin sie sich wirklich
% unterscheiden: Farbe, vertikale Polsterung, Skips und Schrift.
% Der Balken-Ton ist immer Fläche = Rahmen, deshalb ein Schlüssel dafür.
%
% Nach einem Balken kommt zuerst das Umbruchverbot, dann erst der Abstand.
% Die Reihenfolge ist der eigentliche Fix: tcolorbox' "after skip" setzt die
% Glue direkt hinter die Box, und Glue nach einer Box IST ein gültiger
% Umbruchpunkt. Ein \penalty10000, das erst danach kommt, greift zu spät.
% Steht die Sperre davor, ist die Glue durch ein Penalty abgeschirmt und
% damit kein Umbruchpunkt mehr. Deshalb ersetzen die Balken "after skip"
% durch diesen Hook — "after" ersetzt die Default-Aktion von tcolorbox.
\newcommand{\ZSFTitleBarAfter}[1]{%
  \par\penalty10000\vskip#1\relax\ZSFTitleBarLockOn
}

% ------------------------------------------------------------
% Gemeinsame tcb-Stile — die Grundverträge aller Inhaltsboxen
% ------------------------------------------------------------
% Drei Schichten, mehr nicht. Jede konkrete Box steht darauf und setzt
% danach nur noch, worin sie sich WIRKLICH unterscheidet:
%
%   zsfbox       Fluss  — Skips und Eintritts-Hook; gilt auch für rahmenlose
%   zsfboxshape  Form   — Rahmen, Ecken, Innenabstand, Umbruchverhalten
%   zsftitlebox  Titel  — Farben, Titelbalken, Lesbarkeit
%
% Prüffrage vor jedem neuen Stil (rules/10_architecture): Wenn ich den
% Eckenradius ALLER Boxen ändern will — reicht dann eine Zeile? Ein Stil,
% der die Schlüssel eines anderen erneut aufzählt statt ihn zu erweitern,
% ist keine Variante, sondern eine Kopie. Sie driftet beim nächsten Eingriff
% auseinander, und niemand sieht es, weil beide Boxen für sich genommen
% korrekt aussehen. Genau so hatte die formulabox Eckenradius und
% Innenabstand der tcolorbox-Defaults (1mm) statt der ZSF-Werte.
\tcbset{zsftitlebar/.style={
  fonttitle=\ZSFfontBoxTitle\strut,
  halign title=center,
  title style={minimum height=\ZSFtitleBarHeight},
  lefttitle=0pt,
  righttitle=0pt,
  toptitle=\ZSFspaceXS,
  bottomtitle=\ZSFspaceXS,
  before title={},
  after title={},
}}

% Rechtsbuendiges Meta-/Kategorie-Tag im Titelbalken einer Titelbox.
% Verwendung im Titel-Argument der Box, z.B.:
%   \begin{defbox}[Quicksort\ZSFTitleTag{O(n log n)}] ... \end{defbox}
%   \begin{codebox}[Algorithmus\ZSFTitleTag{Python}]  ... \end{codebox}
% Schiebt das Tag per \hfill an den rechten Titelrand. Schrift: \ZSFfontTitleTag.
\newcommand{\ZSFTitleTag}[1]{\hfill{\ZSFfontTitleTag #1}}

% Zum "before"-Schlüssel in allen Box-Stilen unten: das führende \par ist Pflicht.
% "before" ERSETZT die Default-Aktion von tcolorbox (die selbst ein \par enthält) —
% es hängt nicht an. Ohne \par wird eine Box, vor der roher Fliesstext ohne
% Leerzeile steht, inline an den offenen Absatz gehängt: sie bekommt keine
% Spaltenbreite und ragt sichtbar in die Nachbarspalte. Im vertikalen Modus ist
% \par ein No-op, der Zusatz ist also folgenlos, wo ohnehin alles korrekt war.
% Gemeinsamer Grundvertrag aller Inhaltsboxen. Was hier steht, gilt fuer jede
% Box — die einzelnen Stile setzen nur noch ihre Unterschiede. Besonders das
% before-Hook ist Pflicht (Begruendung im Kommentar oben) und darf deshalb
% nicht pro Box wiederholt werden, wo man es vergessen kann.
% Schicht 1 — Fluss. Auch rahmenlose Boxen (weight=quiet, splitbox) laufen
% hierüber, damit Abstände und Balken-Bindung überall identisch greifen.
\tcbset{zsfbox/.style={
  enhanced jigsaw,
  before skip=\ZSFBoxBeforeSkip,
  after skip=\ZSFBoxAfterSkip,
  before={\par\ZSFConsumeAfterSubsectionBar\ZSFTitleBarLockOff},
}}

% ------------------------------------------------------------
% Instanz-Regler — Ebene 3 der Pyramide
% ------------------------------------------------------------
% Was hier steht, war früher pro Box im Stil fest verdrahtet. Genau das war der
% Grund für die Anzahl Boxen: Jede Kombination aus Polsterung, Umbruchverhalten
% und Ausrichtung brauchte einen eigenen Namen. Als benannte Regler sind es
% Eigenschaften einer Box, keine verschiedenen Boxen.
%
% Ein Preset ist ab hier eine LISTE AUS DIESEN REGLERN, nie ein eigener Stil
% (rules/10_architecture → Gestaltung an genau einem Ort). Nur so trifft eine
% Geometrieänderung garantiert jede Box; zwei unabhängige Stildefinitionen
% driften auseinander, ohne dass eine davon für sich falsch aussieht.

% Polsterung ist zweidimensional: waagrecht entscheidet über Kante und
% Balkenfreiraum, senkrecht über die Höhe. Getrennt, weil die Fälle sich
% tatsächlich kreuzen (Wertegitter: waagrecht bündig, senkrecht knapp).
\tcbset{
  padx/.is choice,
  padx/normal/.style={left=\ZSFboxPadX,    right=\ZSFboxPadX},
  padx/bar/.style   ={left=\ZSFboxPadXBar, right=\ZSFboxPadX},
  padx/none/.style  ={left=0pt,            right=0pt},
  pady/.is choice,
  pady/normal/.style={top=\ZSFboxPadY,      bottom=\ZSFboxPadY},
  pady/tight/.style ={top=\ZSFtextMinPad,   bottom=\ZSFtextMinPad},
  pady/quiet/.style ={top=\ZSFboxPadYTight, bottom=\ZSFboxPadYTight},
  pady/none/.style  ={top=0pt,              bottom=0pt},
}

% Ausrichtung des Boxinhalts. Als Hook statt als direktem 'before upper',
% damit die Eintritts-Sequenz einer Box an EINER Stelle steht und die
% Ausrichtung sie nicht ersetzen muss.
\newcommand{\ZSFBoxAlign}{}
% Kontext-Flag der Box (heute nur die formulabox). Ebenfalls Teil derselben
% Sequenz — sonst bräuchte jede Box mit Kontext ein eigenes 'before upper'.
\newcommand{\ZSFBoxContext}{}
% Absatzabstand im Boxinhalt. Textboxen setzen ihn eigenständig (\ZSFspaceS),
% Container um Tabellen und Listen erben den Dokumentwert — dort gibt es keine
% Absätze, und ein eigener Wert würde nur die Liste verschieben.
% Als Regler statt als Auslassung: Vorher fehlte die Zeile in tablebox und
% leisen Box einfach, was von einem Versehen nicht zu unterscheiden war.
\newcommand{\ZSFBoxParskip}{}
% Die Ausrichtung ERSETZT die Justierung, sie ergänzt sie nicht: `align=left`
% ist der Flattersatz für schmale Spalten (55_readability), `align=center` ist
% zentrierter Satz. Beides zusammen wäre kein zentrierter Flattersatz, sondern
% zentrierter Satz mit den Umbruch-Penalties des Flattersatzes — sichtbar an
% anders gebrochenen Formelzeilen.
\tcbset{
  align/.is choice,
  align/left/.style  ={/utils/exec={\renewcommand{\ZSFBoxAlign}{\ZSFReadableAuto}}},
  align/center/.style={/utils/exec={\renewcommand{\ZSFBoxAlign}{\centering}}},
  bodyparskip/.is choice,
  bodyparskip/box/.style={
    /utils/exec={\renewcommand{\ZSFBoxParskip}{\setlength{\parskip}{\ZSFspaceS}}}},
  bodyparskip/inherit/.style={
    /utils/exec={\renewcommand{\ZSFBoxParskip}{}}},
}
% Die Eintritts-Sequenz jeder Box — an genau einer Stelle, aus benannten
% Teilen: Absatzabstand, Justierung, Kontext-Flag, Titelzeile der leisen
% Fassung (leer, solange die Box eine echte Kopfzeile trägt).
\newcommand{\ZSFBoxEnter}{\ZSFBoxParskip\ZSFBoxAlign\ZSFBoxContext\ZSFBoxQuietTitle}

% Rahmen. Der Regler wählt die STÄRKE, die Farbe dazu kommt aus dem Ton —
% deshalb greift er auf dessen Landepunkte zu statt auf feste Farben. Ein
% `frame=soft` überschriebe sonst die Rahmenfarbe eines gewählten Tons.
%
% Ohne Angabe gilt die weiche Rahmenfarbe des Tons — `frame` ist der Regler
% für die Abweichung davon, nicht die Quelle des Defaults (Begründung oben
% bei den Ton-Tokens).
%
% Keiner der drei Werte setzt `boxrule`, ausser wo der Rahmen ganz entfällt.
% Grund: In tcolorbox ist `boxrule` eine Sammeloption und setzt `titlerule`
% mit. Ein erneutes `boxrule=` NACH dem Basisstil holt damit die Linie unter
% dem Titelbalken zurück, die zsfboxshape gerade auf 0pt gesetzt hat — die Box
% wird um die Linienstärke höher, ohne dass am Rahmen etwas sichtbar wäre.
% Die Rahmenstärke selbst gehört zur Form und steht in zsfboxshape.
\tcbset{
  frame/.is choice,
  frame/soft/.style  ={colframe=\ZSFtoneFrameSoft},
  frame/strong/.style={colframe=\ZSFtoneFrameStrong},
  frame/none/.style  ={frame hidden, boxrule=0pt, arc=0pt, outer arc=0pt},
}

% Atomar: bricht nie über eine Spaltengrenze, auch nicht im Pack-Modus.
% Muss in der Optionsliste NACH dem Basisstil stehen — dorthin hängt
% \ZSFBoxesBreakableOn sein 'breakable'. Als benannter Regler ist diese
% Reihenfolge in den Presets festgeschrieben statt in einem Kommentar.
\tcbset{atomic/.style={unbreakable}}

% Schicht 2 — Form. Alles, was die Geometrie JEDER Inhaltsbox bestimmt.
% Wer Rahmenstärke, Ecken oder Innenabstand des Systems ändern will, ändert
% hier — und nur hier. padx/pady gehören dazu, damit \linewidth in jeder Box
% identisch ist (sonst variierende Tabellen-Breiten je Box-Typ).
\tcbset{zsfboxshape/.style={
  zsfbox,
  breakable=false,
  boxsep=0pt,
  boxrule=\ZSFboxRuleWidth,
  titlerule=0pt,
  arc=\ZSFboxArc,
  outer arc=\ZSFboxArc,
  padx=normal,
  pady=normal,
}}

% Farbton einer Box — der Regler, der neue Box-Varianten überflüssig macht
% (rules/02_ai_mandate → Katalog-Ökonomie). Jede Box nimmt ihn als Option
% entgegen: \begin{defbox}[Titel][tone=neutral].
%   chapter  folgt der Kapitelfarbe (Default)
%   neutral  kapitelunabhängig grau — für Boxen, die bewusst NICHT zum
%            Kapitel gehören (Meta-Hinweise, Konventionen, Legenden)
%   warn     rote Kopfzeile (die warnbox verwendet genau diesen Ton)
%
% Der Ton hat vier Wirkungen, nicht drei: Fläche, Rahmen, Kopfzeile — und den
% Akzent. Den Akzent trägt eine rahmenlose Box anstelle der Kopfzeile (linker
% Balken und Titelzeile der leisen Box, Aufzählungszeichen der ZSFlist).
% Er gehört in dieselbe Auswahl, sonst bedeutet derselbe Regler auf zwei Boxen
% zweierlei: `tone=neutral` färbte die Fläche grau, liess den Balken aber
% kapitelfarben — halb umgesetzt, ohne dass etwas meldet.
%
% Die beiden Box-Familien nehmen den Ton an verschiedenen Stellen entgegen:
% eine Titelbox über Fläche und Kopfzeile, eine rahmenlose über Akzent und
% ruhige Fläche. Deshalb setzt jeder Ton BEIDE Landepunkte; welchen eine Box
% liest, entscheidet ihr Stil. Das ist der Grund, warum ein einziger Regler
% genügt und die leise Box trotzdem im Kapitelton ungetönt bleibt.
%
% \ZSFtoneAccent / \ZSFtoneQuietBack werden per /utils/exec gesetzt und sind
% damit auf die Optionen-Gruppe der Box beschränkt; die Farbtokens selbst
% stehen in 40_colors_structure (rules/10_architecture → keine Farbtints hier).
% Die Rahmenfarbe setzt der Ton direkt UND stellt sie als Makro bereit.
% Das ist keine Doppelung, sondern Folge der tcolorbox-Mechanik: `colframe`
% wird beim Setzen der Option sofort aufgelöst (\colorlet), nicht erst beim
% Zeichnen. Ein `colframe=\Makro` nimmt deshalb den Wert an, den das Makro an
% DIESER Stelle der Optionsliste hat — eine spätere Tonwahl erreicht es nicht
% mehr. Also: der Ton setzt die weiche Farbe als Default (wirkt auch, wenn er
% zuletzt kommt), und `frame=strong` greift für die Presets auf das Makro zu.
% Gegenprobe zum Akzent: \ZSFtoneAccent funktioniert als reines Makro, weil
% `borderline` seine Farbe erst beim Zeichnen ausliest.
\newcommand{\ZSFtoneAccent}{\ZSFtoneAccentChapter}
\newcommand{\ZSFtoneQuietBack}{\ZSFtoneQuietBackChapter}
\newcommand{\ZSFtoneFrameSoft}{\ZSFtoneFrameSoftChapter}
\newcommand{\ZSFtoneFrameStrong}{\ZSFtoneFrameStrongChapter}
\tcbset{
  tone/.is choice,
  tone/chapter/.style={
    colback=\BoxBackColor, colbacktitle=\BoxTitleColor,
    colframe=\ZSFtoneFrameSoftChapter, coltitle=\BoxTitleTextColor,
    /utils/exec={\renewcommand{\ZSFtoneAccent}{\ZSFtoneAccentChapter}%
                 \renewcommand{\ZSFtoneQuietBack}{\ZSFtoneQuietBackChapter}%
                 \renewcommand{\ZSFtoneFrameSoft}{\ZSFtoneFrameSoftChapter}%
                 \renewcommand{\ZSFtoneFrameStrong}{\ZSFtoneFrameStrongChapter}}},
  tone/neutral/.style={
    colback=StaticSubBoxBack, colbacktitle=StaticBoxTitleBack,
    colframe=\ZSFtoneFrameSoftNeutral, coltitle=StaticBoxTitleText,
    /utils/exec={\renewcommand{\ZSFtoneAccent}{\ZSFtoneAccentNeutral}%
                 \renewcommand{\ZSFtoneQuietBack}{\ZSFtoneQuietBackNeutral}%
                 \renewcommand{\ZSFtoneFrameSoft}{\ZSFtoneFrameSoftNeutral}%
                 \renewcommand{\ZSFtoneFrameStrong}{\ZSFtoneFrameStrongNeutral}}},
  tone/warn/.style={
    colback=\WarnboxBackColor, colbacktitle=\WarnboxTitleColor,
    colframe=\ZSFtoneFrameSoftWarn, coltitle=\WarnboxTitleTextColor,
    /utils/exec={\renewcommand{\ZSFtoneAccent}{\ZSFtoneAccentWarn}%
                 \renewcommand{\ZSFtoneQuietBack}{\ZSFtoneQuietBackWarn}%
                 \renewcommand{\ZSFtoneFrameSoft}{\ZSFtoneFrameSoftWarn}%
                 \renewcommand{\ZSFtoneFrameStrong}{\ZSFtoneFrameStrongWarn}}},
}

% Schicht 3 — Titelbox. Der EINZIGE Vertrag für Boxen mit Titelbalken; alle
% Presets unten stehen darauf.
%
% Die Eintritts-Sequenz des Boxinhalts steht hier EINMAL und setzt sich aus
% benannten Teilen zusammen: Absatzabstand, Lesbarkeit, Ausrichtung (Regler
% `align`), Kontext-Flag. Vorher hatte fast jede Box ihr eigenes
% 'before upper' und liess dabei je einen Teil weg — die formulabox etwa den
% Flattersatz, die tablebox den Absatzabstand. Solche Auslassungen sind nicht
% erkennbar, weil jede Box für sich plausibel aussieht.
\tcbset{zsftitlebox/.style={
  zsfboxshape,
  tone=chapter,
  align=left,
  bodyparskip=box,
  zsftitlebar,
  % Hooks zurücksetzen, damit eine verschachtelte Box die Einstellungen der
  % äusseren nicht erbt — sie sind gruppenlokal, aber nicht selbstlöschend.
  /utils/exec={\renewcommand{\ZSFBoxContext}{}\renewcommand{\ZSFBoxQuietTitle}{}},
  before upper={\ZSFBoxEnter},
}}

% ------------------------------------------------------------
% Titelbox-Fabrik — ein Aufrufmuster für ALLE Boxen
% ------------------------------------------------------------
% Einheitlicher Aufruf (rules/20_boxes → Aufruf-Konvention):
%   \begin{<box>}[<Titel>][<tcolorbox-Optionen>]
%
% Leerer Titel ⇒ keine Kopfzeile. Ohne diese Fallunterscheidung zeichnet
% tcolorbox bei title={} einen leeren Balken — genau deshalb gab es früher
% pro Box eine titellose Zweitfassung (codebox/zsf@codebox@plain).
\makeatletter
% Die Fallunterscheidung sitzt in einem tcolorbox-Schlüssel, nicht um das
% \begin herum: So gibt es genau EIN \begin{tcolorbox} und genau ein \end —
% sonst zählt chktex sie gegeneinander auf und meldet sie bis zum Dateiende
% als unbalanciert (Warnung 15, dort nicht mehr lokal unterdrückbar).
\tcbset{zsftitle/.code={\IfBlankTF{#1}{\tcbset{notitle}}{\tcbset{title={#1}}}}}
\NewDocumentEnvironment{ZSF@box}{m m m}{%
  \begin{tcolorbox}[#1, zsftitle={#2}, #3]%
}{%
  \end{tcolorbox}%
}
\makeatother

% Das optionale Argument der Bild-Makros war der einzige nackte Wert im
% System: `\ZSFfig[0.7]` gegen `\ZSFtable[header=false]` und
% `\defbox[…][tone=neutral]`. Ein Argument, dessen Bedeutung man nur aus der

% (rules/02_ai_mandate → gleiche Sache, gleiche Bedienung).
%
%   width   Anteil der Zeilenbreite. Bei \ZSFfig die Breite des Bildes bzw.
%           der ganzen Reihe, bei \ZSFfigside der Anteil des Bildes.
%   height  Höhenbegrenzung dieser einen Abbildung.
%
% Die Höhe war vorher NUR global (\ZSFfigMaxHeight) — und fiel still weg,
% sobald man eine Breite angab: der Zweig mit expliziter Breite setzte gar
% kein `height`. Ein hohes Bild sprengte damit genau dann die Spalte, wenn

% \ZSFfig[<Optionen>]{pfad|pfad1,pfad2,…}{Titel}{Caption}
%   EIN Makro für ein Bild und für eine Bildreihe (rules/02_ai_mandate →
%   Katalog-Ökonomie). Eine Pfadliste der Länge 1 IST das Einzelbild —
%   dafür brauchte es früher ein zweites Makro (\ZSFfigrow).
%   Mehrere Pfade: gleiche Breite nebeneinander, abgeleitet aus der Anzahl;
%   `width` begrenzt dann die Reihe insgesamt.
\newcounter{ZSF@figNum}
\newlength{\ZSF@figWidth}
\newcommand{\ZSFfig}[4][]{%
  \begingroup
  \pgfkeys{/zsf/fig, ZSF@figDefaults, #1}%
  \begin{figbox}[{#3}]%
    \setcounter{ZSF@figNum}{0}%
    \@for\ZSF@figItem:=#2\do{\stepcounter{ZSF@figNum}}%
    \ifnum\value{ZSF@figNum}>1\relax
      \setlength{\ZSF@figWidth}{\dimexpr
        \ifx\ZSF@figWidthFrac\@empty\ZSFfigUsableFraction\else\ZSF@figWidthFrac\fi
        \linewidth/\value{ZSF@figNum}\relax}%
      \noindent
      \@for\ZSF@figItem:=#2\do{%
        \begin{minipage}[c]{\ZSF@figWidth}%
          \centering
          \includegraphics[width=\linewidth,height=\ZSF@figHeightLimit,%
            keepaspectratio]{\ZSF@figItem}%
        \end{minipage}%
        \hfill
      }%
      \unskip
      \par
    \else
      \centering
      \setlength{\ZSF@figWidth}{\dimexpr
        \ifx\ZSF@figWidthFrac\@empty 1\else\ZSF@figWidthFrac\fi\linewidth\relax}%
      \includegraphics[width=\ZSF@figWidth,height=\ZSF@figHeightLimit,%
        keepaspectratio]{#2}%
    \fi
    \ZSFfigcaption{#4}%
  \end{figbox}%
  \endgroup
}
