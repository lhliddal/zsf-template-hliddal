% ------------------------------------------------------------
% Balken-Bindung: ein Titelbalken steht nie allein am Spaltenfuss
% ------------------------------------------------------------
% Ein Balken ohne den Anfang seines Inhalts ist der auffälligste Layoutfehler
% einer ZSF: Man sieht die Überschrift, aber nicht, wozu sie gehört.
%
% Eine Platzreserve allein verhindert das nicht, sie verursacht es: Sie besteht
% aus \penalty0 … \penalty-100 und legt damit einen BILLIGEN Umbruchpunkt an
% genau die Stelle, an der ein Balken gerade fertig gesetzt wurde. Ihre Bremse
% — Stretch-Glue, die einen Umbruch bei viel Restplatz unattraktiv macht —
% trägt unter \raggedcolumns nicht, weil multicols den Spaltenboden ohnehin
% frei auffüllt. Übrig bliebe die blosse Einladung zum Umbruch.
%
% Deshalb zwei getrennte Aufgaben statt einer:
%   \ZSFReserveSpace  — „lieber vorher umbrechen, wenn es eng wird" (Bremse)
%   \ZSFTitleBarLock  — „hier NICHT umbrechen, es kam noch kein Inhalt" (Sperre)
% Die Sperre ist die verlässliche; sie hängt an keiner Höhenschätzung.
\newif\ifzsfTitleBarPending
\newcommand{\ZSFTitleBarLockOn}{\global\zsfTitleBarPendingtrue}
\newcommand{\ZSFTitleBarLockOff}{\global\zsfTitleBarPendingfalse}

% Jeder Umbruchpunkt, den das Balken-System selbst setzt, läuft hierüber:
% solange noch kein Inhalt folgte, wird daraus ein Verbot.
\newcommand{\ZSFBarPenalty}[1]{%
  \ifzsfTitleBarPending\penalty10000\else\penalty#1\fi
}

% Platzreserve vor einem Titelbalken: Ist weniger als #1 frei, bricht die
% Spalte davor um. Genau eine Implementierung — die drei Balkenebenen
% unterscheiden sich nur im Schwellwert (rules/30_spacing).
% Direkt hinter einem Balken entfällt sie zugunsten der Sperre.
\newcommand{\ZSFReserveSpace}[1]{%
  \par
  \ifzsfTitleBarPending
    \penalty10000
  \else
    \penalty0\vspace{0pt plus #1}\penalty-100\vspace{0pt plus -#1}%
  \fi
  \relax
}
\newcommand{\BreakIfNotEnoughSpace}{\ZSFReserveSpace{\ZSFbreakThreshold}}
\newcommand{\BreakIfNotEnoughSpaceChapter}{\ZSFReserveSpace{\ZSFbreakThresholdChapter}}
\newcommand{\BreakIfNotEnoughSpaceSubsubsection}{\ZSFReserveSpace{\ZSFbreakThresholdSubsubsection}}

% Einheitlicher Top-Spacing-Kontrakt für Titelbalken.
% Reihenfolge ist kritisch: \addvspace MUSS vor \BreakIfNotEnoughSpace stehen,
% damit es per Max-Semantik mit dem after-skip der Vorbox kollabiert.
% tcolorbox-Definitionen, die diesen Helper rufen, MUESSEN before skip=0pt
% setzen, damit das Spacing nicht doppelt eingerechnet wird.
\newcommand{\ZSFTitleBarTopSpacing}[1]{%
  \par
  \addvspace{#1}%
  \BreakIfNotEnoughSpace
}

% ------------------------------------------------------------
% Titelbalken — gemeinsame Basis
% ------------------------------------------------------------
% Alle vier Balken (Kapitel, Dokumenttitel, Abschnitt, Unterabschnitt) teilen
% denselben Rahmenlos-Kontrakt. Sie setzen nur noch, worin sie sich wirklich
% unterscheiden: Farbe, vertikale Polsterung, Skips und Schrift.
% Der Balken-Ton ist immer Fläche = Rahmen, deshalb ein Schlüssel dafür.
%
% Nach einem Balken kommt zuerst das Umbruchverbot, dann erst der Abstand.
% Die Reihenfolge ist der eigentliche Fix: tcolorbox' "after skip" setzt die
% Glue direkt hinter die Box, und Glue nach einer Box IST ein gültiger
% Umbruchpunkt. Ein \penalty10000, das erst danach kommt, greift zu spät.
% Steht die Sperre davor, ist die Glue durch ein Penalty abgeschirmt und
% damit kein Umbruchpunkt mehr. Deshalb ersetzen die Balken "after skip"
% durch diesen Hook — "after" ersetzt die Default-Aktion von tcolorbox.
\newcommand{\ZSFTitleBarAfter}[1]{%
  \par\penalty10000\vskip#1\relax\ZSFTitleBarLockOn
}

% Gemeinsame tcb-Stile — die Grundverträge aller Inhaltsboxen
% ------------------------------------------------------------
% Drei Schichten, mehr nicht. Jede konkrete Box steht darauf und setzt
% danach nur noch, worin sie sich WIRKLICH unterscheidet:
%
%   zsfbox       Fluss  — Skips und Eintritts-Hook; gilt auch für rahmenlose
%   zsfboxshape  Form   — Rahmen, Ecken, Innenabstand, Umbruchverhalten
%   zsftitlebox  Titel  — Farben, Titelbalken, Lesbarkeit
%
% Prüffrage vor jedem neuen Stil (rules/10_architecture): Wenn ich den
% Eckenradius ALLER Boxen ändern will — reicht dann eine Zeile? Ein Stil,
% der die Schlüssel eines anderen erneut aufzählt statt ihn zu erweitern,
% ist keine Variante, sondern eine Kopie. Sie driftet beim nächsten Eingriff
% auseinander, und niemand sieht es, weil beide Boxen für sich genommen
% korrekt aussehen.
\tcbset{zsftitlebar/.style={
  fonttitle=\ZSFfontBoxTitle\strut,
  halign title=center,
  title style={minimum height=\ZSFtitleBarHeight},
  lefttitle=0pt,
  righttitle=0pt,
  toptitle=\ZSFspaceXS,
  bottomtitle=\ZSFspaceXS,
  before title={},
  after title={},
}}

%   \begin{codebox}[Algorithmus\ZSFTitleTag{Python}]  ... \end{codebox}
% Schiebt das Tag per \hfill an den rechten Titelrand. Schrift: \ZSFfontTitleTag.
\newcommand{\ZSFTitleTag}[1]{\hfill{\ZSFfontTitleTag #1}}

% Zum "before"-Schlüssel in allen Box-Stilen unten: das führende \par ist Pflicht.
% "before" ERSETZT die Default-Aktion von tcolorbox (die selbst ein \par enthält) —
% es hängt nicht an. Ohne \par wird eine Box, vor der roher Fliesstext ohne
% Leerzeile steht, inline an den offenen Absatz gehängt: sie bekommt keine
% Spaltenbreite und ragt sichtbar in die Nachbarspalte. Im vertikalen Modus ist
% \par ein No-op, der Zusatz ist also folgenlos, wo ohnehin alles korrekt war.
% Gemeinsamer Grundvertrag aller Inhaltsboxen. Was hier steht, gilt fuer jede
% Box — die einzelnen Stile setzen nur noch ihre Unterschiede. Besonders das
% before-Hook ist Pflicht (Begruendung im Kommentar oben) und darf deshalb
% nicht pro Box wiederholt werden, wo man es vergessen kann.
% Schicht 1 — Fluss. Auch rahmenlose Boxen (weight=quiet, splitbox) laufen
% hierüber, damit Abstände und Balken-Bindung überall identisch greifen.
\tcbset{zsfbox/.style={
  enhanced jigsaw,
  before skip=\ZSFBoxBeforeSkip,
  after skip=\ZSFBoxAfterSkip,
  before={\par\ZSFConsumeAfterSubsectionBar\ZSFTitleBarLockOff},
}}

% Instanz-Regler — Ebene 3 der Pyramide
% ------------------------------------------------------------
% Polsterung, Umbruchverhalten und Ausrichtung sind Eigenschaften einer Box,
% keine verschiedenen Boxen. Fest im Stil verdrahtet, bräuchte jede Kombination
% davon einen eigenen Namen — als benannte Regler genügt einer.
%
% Ein Preset ist ab hier eine LISTE AUS DIESEN REGLERN, nie ein eigener Stil
% (rules/10_architecture → Gestaltung an genau einem Ort). Nur so trifft eine
% Geometrieänderung garantiert jede Box; zwei unabhängige Stildefinitionen
% driften auseinander, ohne dass eine davon für sich falsch aussieht.

% Rahmen — der Regler wählt die STÄRKE, die Farbe dazu kommt aus dem Ton.
%
% Der Regler setzt `colframe` NICHT selbst, sondern merkt sich nur die Wahl;
% aufgelöst wird sie als letzte Option jeder Box (ZSF@resolveframe, unten an
% der Fabrik). Das ist keine Umständlichkeit, sondern die einzige Form, in der
% der Regler verlässlich ist: tcolorbox löst `colframe` beim Setzen der Option
% sofort per \colorlet auf. Wer den Rahmen früh in der Liste festlegt, verliert
% ihn deshalb an jede spätere Option, die ebenfalls `colframe` schreibt — und
% ein Ton schreibt es. Ein `\begin{goalbox}[T][tone=warn]` bekäme so weder den
% kräftigen Rahmen der Zielkette noch die Rahmenfarbe des Warn-Tons, sondern
% den weichen Kapitelrahmen — stumm, weil beide Werte für sich gültig sind
% (rules/02_ai_mandate → Randverhalten I).
%
% Verzögert ist die Reihenfolge dagegen bedeutungslos: Stärke und Ton stehen
% beide fest, wenn der Resolver läuft, egal wer sie gesetzt hat.
%
% Keiner der Stärke-Werte setzt `boxrule`, ausser wo der Rahmen ganz entfällt.
% Grund: In tcolorbox ist `boxrule` eine Sammeloption und setzt `titlerule`
% mit. Ein erneutes `boxrule=` NACH dem Basisstil holt damit die Linie unter
% dem Titelbalken zurück, die zsfboxshape gerade auf 0pt gesetzt hat — die Box
% wird um die Linienstärke höher, ohne dass am Rahmen etwas sichtbar wäre.
% Die Rahmenstärke selbst gehört zur Form und steht in zsfboxshape.
\makeatletter
\newcommand{\ZSF@frameChoice}{soft}
\tcbset{
  frame/.is choice,
  frame/soft/.code  ={\renewcommand{\ZSF@frameChoice}{soft}},
  frame/strong/.code={\renewcommand{\ZSF@frameChoice}{strong}},
  frame/hard/.code  ={\renewcommand{\ZSF@frameChoice}{hard}},
  frame/none/.code  ={\renewcommand{\ZSF@frameChoice}{none}},
}
% Läuft als letzte Option jeder Box und übersetzt die gemerkte Stärke gegen
% den dann feststehenden Ton. Jede Box, die einen Rahmen haben kann, muss ihn
% durchlaufen — sonst bleibt sie beim tcolorbox-Default.
\tcbset{ZSF@resolveframe/.code={%
  \IfStrEqCase{\ZSF@frameChoice}{%
    {soft}  {\tcbset{colframe=\ZSFtoneFrameSoft}}%
    {strong}{\tcbset{colframe=\ZSFtoneFrameStrong}}%
    {hard}  {\tcbset{colframe=\ZSFtoneFrameHard}}%
    {none}  {\tcbset{frame hidden, boxrule=0pt, arc=0pt, outer arc=0pt}}%
  }%
}}
\makeatother

\tcbset{atomic/.style={unbreakable}}

% Wer Rahmenstärke, Ecken oder Innenabstand des Systems ändern will, ändert

  outer arc=\ZSFboxArc,

  frame=soft,
}}

% Farbton einer Box — der Regler, der neue Box-Varianten überflüssig macht
% (rules/02_ai_mandate → Katalog-Ökonomie). Jede Box nimmt ihn als Option
% entgegen: \begin{defbox}[Titel][tone=neutral].
%   chapter  folgt der Kapitelfarbe (Default)
%   neutral  kapitelunabhängig grau — für Boxen, die bewusst NICHT zum
%            Kapitel gehören (Meta-Hinweise, Konventionen, Legenden)
%   warn     rote Kopfzeile (die warnbox verwendet genau diesen Ton)
%
% Der Ton hat vier Wirkungen, nicht drei: Fläche, Rahmen, Kopfzeile — und den
% Akzent. Den Akzent trägt eine rahmenlose Box anstelle der Kopfzeile (linker
% Balken und Titelzeile der leisen Box, Aufzählungszeichen der ZSFlist).
% Er gehört in dieselbe Auswahl, sonst bedeutet derselbe Regler auf zwei Boxen
% zweierlei: `tone=neutral` färbte die Fläche grau, liess den Balken aber
% kapitelfarben — halb umgesetzt, ohne dass etwas meldet.
%
% Die beiden Box-Familien nehmen den Ton an verschiedenen Stellen entgegen:
% eine Titelbox über Fläche und Kopfzeile, eine rahmenlose über Akzent und
% ruhige Fläche. Deshalb setzt jeder Ton BEIDE Landepunkte; welchen eine Box
% liest, entscheidet ihr Stil. Das ist der Grund, warum ein einziger Regler
% genügt und die leise Box trotzdem im Kapitelton ungetönt bleibt.
%
% Alle Landepunkte werden per /utils/exec als Makro gesetzt und sind damit auf
% die Optionen-Gruppe der Box beschränkt; die Farbtokens selbst stehen in
% 40_colors_structure (rules/10_architecture → keine Farbtints hier).
%
% Auch die Rahmenfarben sind reine Makros: Der Ton legt sie ab, aufgelöst
% werden sie erst vom Rahmen-Resolver am Ende der Optionsliste. Dadurch ist es
% gleichgültig, ob der Ton vor oder nach der Rahmenwahl steht.
%
% Die FLÄCHE nimmt der Ton nicht als einen Wert entgegen, sondern als beide:
% die laute und die ruhige. Welche davon gesetzt wird, entscheidet die
% Gewicht-Wahl, die zu diesem Zeitpunkt bereits feststeht.
%
% Warum nicht einfach `colback` und die leise Box überschreibt es? Weil
% `colback` sofort per \colorlet aufgelöst wird und damit dem letzten
% Schreiber gehört. Setzte der Ton die laute Fläche und das Gewicht danach
% die ruhige, entschiede die Reihenfolge im Aufruf — und ein ausgeschriebenes
% `tone=chapter` tönte eine leise Box, ein weggelassenes nicht. Derselbe
% Aufruf mit und ohne Default sähe verschieden aus, ohne dass etwas meldet.
% Hier trifft stattdessen jeder Ton beide Fälle und wählt selbst.
\newcommand{\ZSFtoneAccent}{\ZSFtoneAccentChapter}
\newcommand{\ZSFtoneQuietBack}{\ZSFtoneQuietBackChapter}
\newcommand{\ZSFtoneFrameSoft}{\ZSFtoneFrameSoftChapter}
\newcommand{\ZSFtoneFrameStrong}{\ZSFtoneFrameStrongChapter}
\newcommand{\ZSFtoneFrameHard}{\ZSFtoneFrameHardChapter}
\makeatletter
\tcbset{ZSF@toneSurface/.code 2 args={%
  \ifZSF@boxQuiet\tcbset{colback=#2}\else\tcbset{colback=#1}\fi
}}
\makeatother
\tcbset{
  tone/.is choice,
  tone/chapter/.style={

    colbacktitle=\BoxTitleColor,
    coltitle=\BoxTitleTextColor,

                 \renewcommand{\ZSFtoneQuietBack}{\ZSFtoneQuietBackChapter}%
                 \renewcommand{\ZSFtoneFrameSoft}{\ZSFtoneFrameSoftChapter}%
                 \renewcommand{\ZSFtoneFrameStrong}{\ZSFtoneFrameStrongChapter}%
                 \renewcommand{\ZSFtoneFrameHard}{\ZSFtoneFrameHardChapter}}},
  tone/neutral/.style={

% Presets unten stehen darauf.

% ------------------------------------------------------------
% Titelbox-Fabrik — ein Aufrufmuster für ALLE Boxen
% ------------------------------------------------------------
% Einheitlicher Aufruf (rules/20_boxes → Aufruf-Konvention):
%   \begin{<box>}[<Titel>][<tcolorbox-Optionen>]
%
% Leerer Titel ⇒ keine Kopfzeile. Ohne diese Fallunterscheidung zeichnet
% tcolorbox bei title={} einen leeren Balken, und jede Box bräuchte eine
% titellose Zweitfassung.
\makeatletter
% Die Fallunterscheidung sitzt in einem tcolorbox-Schlüssel, nicht um das
% \begin herum: So gibt es genau EIN \begin{tcolorbox} und genau ein \end —
% sonst zählt chktex sie gegeneinander auf und meldet sie bis zum Dateiende
% als unbalanciert (Warnung 15, dort nicht mehr lokal unterdrückbar).
\tcbset{zsftitle/.code={\IfBlankTF{#1}{\tcbset{notitle}}{\tcbset{title={#1}}}}}
% Der Titel wird zusätzlich gemerkt, weil `weight=quiet` die Kopfzeile
% abschaltet und ihn stattdessen als erste Inhaltszeile setzt. Das gehört in
% die Fabrik und nicht in eine einzelne Umgebung: Stand es nur in der defbox,
% dann verschluckte `weight=quiet` auf jeder anderen Box den Titel stillschweigend
% — die Kopfzeile war abgeschaltet, die Ersatzzeile fand nichts zu setzen.
% Ein Regler, der auf einer Box Inhalt verliert, ist schlimmer als einer, der
% dort gar nicht gilt (rules/02_ai_mandate → gleiche Sache, gleiche Bedienung).
%
% ZSF@resolveframe steht bewusst als LETZTE Option: erst danach ist der Rahmen
% aus Stärke und Ton zusammengesetzt, unabhängig davon, in welcher Reihenfolge
% Preset und Aufrufer sie gewählt haben.
%
% Vor-Lauf für das Gewicht. `weight` ist der einzige Regler, der keinen WERT
% wählt, sondern den BASISSTIL — und ein Basisstil bringt Vorbelegungen mit.
% Stünde er wie die übrigen Regler in der Aufrufer-Liste, liefen seine
% Vorbelegungen nach den Wahlen des Aufrufers und überschrieben sie. Genau das
% war der Fall: `[tone=warn, weight=quiet]` verlor den Ton, `[frame=strong,
% weight=quiet]` den Rahmen — stumm, weil beide Werte für sich gültig sind.
%
% Deshalb wird die Wahl hier vorab aus der Liste gelesen und die fertige Basis
% VOR die Aufrufer-Optionen gesetzt. Danach gilt für jeden Regler dieselbe
% Reihenfolge: Vorbelegung, dann Aufrufer. Dasselbe Muster liest \ZSFfig schon
% für `width`/`height` aus seiner Optionsliste.
%
% .unknown verwirft hier alles andere — es wird gleich darauf in der echten
% Optionsliste ausgewertet. Absolute Schlüsselpfade (/utils/exec) umgehen die
% Familie und laufen im Vor-Lauf mit; in Kapiteln kommen sie nicht vor, und der
% Linter meldet rohe tcolorbox-Eingriffe ohnehin.
\pgfkeys{
  /zsf/boxweight/.is family, /zsf/boxweight,
  weight/.is choice,
  weight/loud/.code ={\ZSF@boxQuietfalse},
  weight/quiet/.code={\ZSF@boxQuiettrue},
  .unknown/.code={},% chktex 26
}

  % Stil den Merker nicht zurücksetzt, die Titelzeile der Box, in der sie steht.
  \renewcommand{\ZSFBoxQuietTitle}{}%
  \ZSF@boxQuietfalse
  \pgfkeys{/zsf/boxweight, #3}%

% ist ein Einzeiler. Wer beides entkoppeln muss, bekommt einen Regler — aber

  \else

      leftmargin=\ZSFlistLeftMargin, labelsep=\ZSFlistLabelSep,
      label={\textcolor{\ZSFtoneAccent}{\textbullet}},

% Ohne Titel entsteht keine Box — und damit kein Träger für die Box-Regler.
% `ordered` und `tone` wirken trotzdem, weil die Liste beide selbst liest
% (Nummerierung; Farbe des Aufzählungszeichens). Jeder andere Regler hat hier
% nichts, worauf er wirken könnte, und verschwand bisher stumm: `\tcbset`
% nahm ihn entgegen, und niemand las ihn je wieder.
%
% Er wird deshalb gemeldet statt geschluckt. Ein Regler, der auf einer Box
% wirkungslos ist, ohne dass etwas sagt, ist die teuerste Fehlerart des
% Systems — teurer als ein fehlendes Feature, weil er die Vorhersagbarkeit
% aller übrigen Regler mit entwertet (rules/02_ai_mandate → Randverhalten I).

  /zsf/listplain/.is family, /zsf/listplain,
  ordered/.code={\tcbset{ordered=#1}},
  ordered/.default=true,
  tone/.code={\tcbset{tone=#1}},
  .unknown/.code={% chktex 26
    \PackageError{ZSF}{%

% ------------------------------------------------------------
% Pack-Modus für Anhang-artige Kapitel
% ------------------------------------------------------------
% Ersetzen rohes \tcbset und \renewcommand im Kapitel — beides ist
% Systemumbau und bricht den Linter (rules/02_ai_mandate). Am Anfang des
% betreffenden Kapitels aufrufen; die Wirkung endet mit dessen Gruppe.
%
% Wichtig: Ein globales \tcbset{breakable} im Kapitel hätte ohnehin nicht
% gewirkt — zsfboxshape setzt breakable=false in seiner eigenen Optionsliste
% und gewinnt damit gegen den Default. Deshalb hängen diese Schalter die
% Option an die Stile selbst an.
%
% Bewusst NICHT breakable: figbox, valuegrid, goalbox und die Balken. Ein
% Umbruch mitten in Bild, Wertegrid oder Zielkette ergibt keinen Sinn. Die
% drei erzwingen das mit einem 'unbreakable' NACH zsftitlebox: Was diese
% Schalter anhängen, steht in der Optionsliste davor und verliert dagegen.
\newcommand{\ZSFBoxesBreakableOn}{%
  \tcbset{zsftitlebox/.append style={breakable},
          preset/quiet/.append style={breakable}}%
}
\newcommand{\ZSFBoxesBreakableOff}{%
  \tcbset{zsftitlebox/.append style={breakable=false},
          preset/quiet/.append style={breakable=false}}%
}
