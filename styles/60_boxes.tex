% ------------------------------------------------------------
% Balken-Bindung: ein Titelbalken steht nie allein am Spaltenfuss
% ------------------------------------------------------------
% Ein Balken ohne den Anfang seines Inhalts ist der auffälligste Layoutfehler
% einer ZSF: Man sieht die Überschrift, aber nicht, wozu sie gehört.
%
% Eine Platzreserve allein verhindert das nicht, sie verursacht es: Sie besteht
% aus \penalty0 … \penalty-100 und legt damit einen BILLIGEN Umbruchpunkt an
% genau die Stelle, an der ein Balken gerade fertig gesetzt wurde. Ihre Bremse
% — Stretch-Glue, die einen Umbruch bei viel Restplatz unattraktiv macht —
% trägt unter \raggedcolumns nicht, weil multicols den Spaltenboden ohnehin
% frei auffüllt. Übrig bliebe die blosse Einladung zum Umbruch.
%
% Deshalb zwei getrennte Aufgaben statt einer:
%   \ZSFReserveSpace  — „lieber vorher umbrechen, wenn es eng wird" (Bremse)
%   \ZSFTitleBarLock  — „hier NICHT umbrechen, es kam noch kein Inhalt" (Sperre)
% Die Sperre ist die verlässliche; sie hängt an keiner Höhenschätzung.
%
% Gelöscht wird die Sperre vom ERSTEN Absatz danach — Box, runintext oder
% blanker Fliesstext. Der \everypar-Haken ist der einzige Ort, an dem TeX
% »hier beginnt Inhalt« zuverlässig meldet; \ZSF@blockBefore allein genügt
% nicht, denn den durchläuft nur eine Box. Ohne den Haken blieb die Sperre
% nach »Balken → Fliesstext« stehen — und weil ALLE Leser unten sie lesen,
% hiess das: Box-Vorabstand übersprungen, Balken-Penalty und Platzreserve
% dauerhaft auf »Verbot«. Drei Mechanismen liefen praktisch nie.
% \everypar ist im Template sonst unbenutzt (auch multicol rührt es nicht an);
% \global, weil der Haken sonst in der Gruppe verfällt, in der er zündet.
\newif\ifzsfTitleBarPending
\newcommand{\ZSFTitleBarLockOn}{%
  \global\zsfTitleBarPendingtrue
  \global\everypar{\ZSFTitleBarLockOff}%
}
\newcommand{\ZSFTitleBarLockOff}{%
  \global\zsfTitleBarPendingfalse
  \global\everypar{}%
}

% Umbruchsteuerung an Balken — der Schalter für BEIDE Mechanismen unten
% (\ZSFBarPenalty, \ZSFReserveSpace). Aus über \ZSFBreakReservesOff.
%
% Was der Schalter NICHT abschaltet: das \penalty10000, solange die Sperre
% steht. Das ist keine Steuerung, sondern die Zusage, dass ein Balken nicht
% als letztes Element einer Spalte stehenbleibt.
\newif\ifZSFBarSteering \ZSFBarSteeringtrue

% Jeder Umbruchpunkt, den das Balken-System selbst setzt, läuft hierüber:
% solange noch kein Inhalt folgte, wird daraus ein Verbot.
\newcommand{\ZSFBarPenalty}[1]{%
  \ifzsfTitleBarPending\penalty10000\else\ifZSFBarSteering\penalty#1\fi\fi
}

% Platzreserve vor einem Titelbalken: Ist weniger als #1 frei, bricht die
% Spalte davor um. Genau eine Implementierung — die drei Balkenebenen
% unterscheiden sich nur im Schwellwert (rules/30_spacing).
% Direkt hinter einem Balken entfällt sie zugunsten der Sperre.
\newcommand{\ZSFReserveSpace}[1]{%
  \par
  \ifzsfTitleBarPending
    \penalty10000
  \else
    \penalty0\vspace{0pt plus #1}\penalty-100\vspace{0pt plus -#1}%
  \fi
  \relax
}
\newcommand{\BreakIfNotEnoughSpace}{\ZSFReserveSpace{\ZSFbreakThreshold}}
\newcommand{\BreakIfNotEnoughSpaceChapter}{\ZSFReserveSpace{\ZSFbreakThresholdChapter}}
\newcommand{\BreakIfNotEnoughSpaceSubsubsection}{\ZSFReserveSpace{\ZSFbreakThresholdSubsubsection}}

% Einheitlicher Top-Spacing-Kontrakt für Titelbalken.
% Reihenfolge ist kritisch: \addvspace MUSS vor \BreakIfNotEnoughSpace stehen,
% damit es per Max-Semantik mit dem after-skip der Vorbox kollabiert.
% tcolorbox-Definitionen, die diesen Helper rufen, MUESSEN before skip=0pt
% setzen, damit das Spacing nicht doppelt eingerechnet wird.
\newcommand{\ZSFTitleBarTopSpacing}[1]{%
  \par
  \addvspace{#1}%
  \BreakIfNotEnoughSpace
}

% ------------------------------------------------------------
% Titelbalken — gemeinsame Basis
% ------------------------------------------------------------
% Alle vier Balken (Kapitel, Dokumenttitel, Abschnitt, Unterabschnitt) teilen
% denselben Rahmenlos-Kontrakt. Sie setzen nur noch, worin sie sich wirklich
% unterscheiden: Farbe, vertikale Polsterung, Skips und Schrift.
% Der Balken-Ton ist immer Fläche = Rahmen, deshalb ein Schlüssel dafür.
%
% Nach einem Balken kommt zuerst das Umbruchverbot, dann erst der Abstand.
% Die Reihenfolge ist der eigentliche Fix: tcolorbox' "after skip" setzt die
% Glue direkt hinter die Box, und Glue nach einer Box IST ein gültiger
% Umbruchpunkt. Ein \penalty10000, das erst danach kommt, greift zu spät.
% Steht die Sperre davor, ist die Glue durch ein Penalty abgeschirmt und
% damit kein Umbruchpunkt mehr. Deshalb ersetzen die Balken "after skip"
% durch diesen Hook — "after" ersetzt die Default-Aktion von tcolorbox.
%
% Der Abstand selbst ist \ZSFbarAfterGap und steht deshalb NICHT mehr als
% Argument hier: Ein Balken ist ein Balken, und was unter ihm frei bleibt, ist
% eine Entscheidung des Systems und keine der vier Balkendefinitionen
% (rules/02_ai_mandate → Katalog-Ökonomie). Gesetzt wird er über
% \ZSFInterlude (30_layout_spacing) statt über ein rohes \vskip — nur so ist
% der Abstand der GANZE Abstand: \ZSFInterlude zieht \parskip ab, den der
% folgende Absatz selbst setzt, und nimmt mit \nointerlineskip die
% Zeilenschaltung heraus. Ohne beides kamen zu jedem gesetzten Wert noch 3.5pt
% Absatzabstand und eine inhaltsabhängige Zeilenschaltung hinzu — der Abstand
% war dann das Nebenprodukt der Tinte und nicht der gesetzte Wert.
\newcommand{\ZSFTitleBarAfter}{%
  \par\penalty10000\ZSFInterlude{\ZSFbarAfterGap}\ZSFTitleBarLockOn
}

\tcbset{
  zsfbarcolor/.style={colback=#1, colframe=#1},
  zsfbar/.style={
    enhanced jigsaw,
    breakable=false,
    boxrule=0pt,
    boxsep=0pt,
    arc=\ZSFboxArc,
    outer arc=\ZSFboxArc,
    left=\ZSFboxPadX,
    right=\ZSFboxPadX,
    before skip=0pt,
    % HIER KEIN `after skip`. Was unter einem Balken frei bleibt, setzt
    % \ZSFTitleBarAfter vollständig; die vier Balken hängen es unten als
    % `after={\ZSFTitleBarAfter}` ein und ersetzen damit die Default-Aktion.
    %
    % `after skip` daneben zu setzen sieht harmlos aus und ist es nicht:
    % Es ist — wie `before skip`, siehe styles/README — kein Schlüssel,
    % sondern ein Stil, der `after` schreibt, mit dem Rumpf
    % `\addvspace{\glueexpr#1-\parskip}`. Selbst mit #1=0pt steht danach ein
    % `-\parskip` hinter der Box. tcolorbox darf das, weil der folgende Absatz
    % \parskip selbst zurückzahlt — nur zieht \ZSFInterlude ihn hier ein
    % zweites Mal ab, und zurückgezahlt wird er einmal. Der Abstand unter
    % jedem Balken ist dann um einen vollen \parskip zu klein, der Satz läuft
    % in die Balkenkante. Genau so passiert, deshalb steht es hier.
  },
}

% ------------------------------------------------------------
% Gemeinsame tcb-Stile — die Grundverträge aller Inhaltsboxen
% ------------------------------------------------------------
% Drei Schichten, mehr nicht. Jede konkrete Box steht darauf und setzt
% danach nur noch, worin sie sich WIRKLICH unterscheidet:
%
%   zsfbox       Fluss  — Skips und Eintritts-Hook; gilt auch für rahmenlose
%   zsfboxshape  Form   — Rahmen, Ecken, Innenabstand, Umbruchverhalten
%   zsftitlebox  Titel  — Farben, Titelbalken, Lesbarkeit
%
% Prüffrage vor jedem neuen Stil (rules/10_architecture): Wenn ich den
% Eckenradius ALLER Boxen ändern will — reicht dann eine Zeile? Ein Stil,
% der die Schlüssel eines anderen erneut aufzählt statt ihn zu erweitern,
% ist keine Variante, sondern eine Kopie. Sie driftet beim nächsten Eingriff
% auseinander, und niemand sieht es, weil beide Boxen für sich genommen
% korrekt aussehen.
% \ZSFInkOwned im fonttitle: Der Titelbalken setzt `coltitle` und besitzt damit
% die Farbe — in jedem Ton, nicht nur im gesaettigten Warn-Ton
% (40_colors_structure -> Ink-Vertrag). Der Hook laeuft in der Titel-Gruppe und
% ist deshalb auf sie beschraenkt.
% Der WAAGRECHTE Innenabstand steht bewusst NICHT hier, sondern beim Regler
% `padx` weiter unten. Er ist keine Eigenschaft des Titelbalkens, sondern die
% eine Kante, an der Titel und Inhalt gemeinsam stehen: Steht sie zweimal,
% steht sie beim naechsten Eingriff einmal anders — und genau das war der Fall.
% `lefttitle`/`righttitle` waren hier auf 0pt festgenagelt, waehrend der Inhalt
% \ZSFboxPadX (4 pt) bzw. in der tablebox \ZSFtableEdgePad (7 pt) einhielt. Der
% Titel klebte damit in JEDER Box an der Kante, und die formulabox hatte es als
% einzige lokal repariert — eine Kopie statt einer Variante
% (rules/10_architecture → Gestaltung an genau einem Ort).
% Der Titelbalken fuellt die Box ohnehin in voller Breite; `lefttitle` ruecken
% nur den Text ein und kosten nichts.
\tcbset{zsftitlebar/.style={
  fonttitle=\ZSFfontBoxTitle\ZSFInkOwned\strut,
  halign title=center,
  title style={minimum height=\ZSFtitleBarHeight},
  toptitle=\ZSFspaceXS,
  bottomtitle=\ZSFspaceXS,
  before title={},
  after title={},
}}

% Rechtsbuendiges Meta-/Kategorie-Tag im Titelbalken einer Titelbox.
% Verwendung im Titel-Argument der Box, z.B.:
%   \begin{defbox}[Quicksort\ZSFTitleTag{O(n log n)}] ... \end{defbox}
%   \begin{codebox}[Algorithmus\ZSFTitleTag{Python}]  ... \end{codebox}
% Schiebt das Tag per \hfill an den rechten Titelrand. Schrift: \ZSFfontTitleTag.
\newcommand{\ZSFTitleTag}[1]{\hfill{\ZSFfontTitleTag #1}}

% Zum "before"-Schlüssel in allen Box-Stilen unten: das führende \par ist Pflicht.
% "before" ERSETZT die Default-Aktion von tcolorbox (die selbst ein \par enthält) —
% es hängt nicht an. Ohne \par wird eine Box, vor der roher Fliesstext ohne
% Leerzeile steht, inline an den offenen Absatz gehängt: sie bekommt keine
% Spaltenbreite und ragt sichtbar in die Nachbarspalte. Im vertikalen Modus ist
% \par ein No-op, der Zusatz ist also folgenlos, wo ohnehin alles korrekt war.
% Gemeinsamer Grundvertrag aller Inhaltsboxen. Was hier steht, gilt fuer jede
% Box — die einzelnen Stile setzen nur noch ihre Unterschiede. Besonders das
% before-Hook ist Pflicht (Begruendung im Kommentar oben) und darf deshalb
% nicht pro Box wiederholt werden, wo man es vergessen kann.
% Schicht 1 — Fluss. Auch rahmenlose Boxen (weight=quiet, splitbox) laufen
% hierüber, damit Abstände und Balken-Bindung überall identisch greifen.
% DER ABSTAND VOR EINEM BLOCK — eine Stelle, und sie muss es sein.
%
% Hier standen `before skip` und `before` nebeneinander. In tcolorbox ist
% `before skip` aber KEIN eigener Schluessel, sondern ein Stil, der `before`
% schreibt (tcolorbox.sty: `before skip/.style={before={...}}`). Beide
% schreiben also dasselbe Makro, und der spaetere gewinnt — `before` stand
% hinten, damit war \ZSFBoxBeforeSkip wirkungslos. Nachgemessen: auf 40pt
% gesetzt aendert sich am Satz nichts.
%
% Die Folgen reichten weiter als der eine Wert: Der Abstand vor JEDER Box kam
% damit allein aus \parskip und gehoerte keinem Register. Die Kollaps-Mechanik
% nach einem Balken (damals \ifzsfAfterSubsectionBar) rechnete einen Wert aus, den
% niemand las, und \ZSFboxgroup schloss seine Zwischenraeume nicht wirklich.
%
% Deshalb EIN `before`, das beides tut. Die Skip-Logik ist die von tcolorbox
% selbst — dieselben Faelle (nichts auf der Liste, vertikaler Modus), damit
% hier keine zweite Auslegung derselben Frage entsteht. Gelesen wird
% \ZSFBoxBeforeSkip VOR dem Verbrauch des Merkers: Der Merker waehlt den Wert.
%
% Den Minipage-Sonderfall von tcolorbox braucht es nicht: \addvspace prueft
% LaTeXs eigenes @minipage selbst und tut am Anfang einer Minipage nichts —
% genau das, was jener Zweig von Hand herstellt. Ihn nachzubauen hiesse,
% \iftcb@minipage zu lesen, und das existiert ausserhalb einer tcolorbox gar
% nicht (gemessen: undefined im runintext).
\makeatletter
\newcommand{\ZSF@blockBefore}{%
  \ifnum\lastnodetype=-1\relax\else
    \par
    \ifvmode
      % Die Sperre gilt auch fuer den Vorabstand DIESES Blocks, nicht nur fuer
      % die Umbruchpunkte, die das Balken-System selbst setzt.
      %
      % Warum das noetig ist: Direkt nach einem Balken steht
      % \penalty10000 + Glue — dort ist kein Bruch moeglich, weil eine Glue
      % nach einer Penalty kein legaler Umbruchpunkt ist. Steht zwischen Balken
      % und Block aber ein NICHT-verwerfbarer Knoten, ist die Kette
      % unterbrochen: \ZSFindex schreibt einen \write-Whatsit, \label ebenso.
      % Danach ist die naechste Glue wieder ein legaler Umbruchpunkt, und der
      % Balken bleibt allein am Spaltenfuss stehen. Genau so gesehen im Anhang,
      % wo \ZSFBreakReservesOff die zweite Absicherung wegnimmt.
      %
      % Nur wenn KEINE Glue zum Verschmelzen daliegt: Ist \lastskip von null
      % verschieden, zieht \addvspace die vorhandene Glue ein und die
      % \penalty10000 des Balkens steht wieder unmittelbar davor — dort waere
      % ein \nobreak wirkungslos und wuerde die Verschmelzung verhindern, also
      % zusaetzlichen Abstand erzeugen.
      \ifzsfTitleBarPending\ifdim\lastskip=0pt\nobreak\fi\fi
      \addvspace{\glueexpr\ZSFBoxBeforeSkip-\parskip\relax}%
    \fi
  \fi
  % BEIDE Merker, nicht nur der eine. Ein Block zwischen Kapitelbalken und
  % Abschnittsbalken heisst, dass die beiden Balken NICHT aneinanderstossen —
  % blieb der Kapitel-Merker stehen, zog der Abschnittsbalken seinen Vorabstand
  % trotzdem zusammen. Derselbe Fehler eine Ebene hoeher.
  \ZSFTitleBarLockOff
}
\tcbset{zsfbox/.style={
  enhanced jigsaw,
  after skip=\ZSFBoxAfterSkip,
  before={\ZSF@blockBefore},
}}
\makeatother

% ------------------------------------------------------------
% Instanz-Regler — Ebene 3 der Pyramide
% ------------------------------------------------------------
% Polsterung, Umbruchverhalten und Ausrichtung sind Eigenschaften einer Box,
% keine verschiedenen Boxen. Fest im Stil verdrahtet, bräuchte jede Kombination
% davon einen eigenen Namen — als benannte Regler genügt einer.
%
% Ein Preset ist ab hier eine LISTE AUS DIESEN REGLERN, nie ein eigener Stil
% (rules/10_architecture → Gestaltung an genau einem Ort). Nur so trifft eine
% Geometrieänderung garantiert jede Box; zwei unabhängige Stildefinitionen
% driften auseinander, ohne dass eine davon für sich falsch aussieht.

% Polsterung ist zweidimensional: waagrecht entscheidet über Kante und
% Balkenfreiraum, senkrecht über die Höhe. Getrennt, weil die Fälle sich
% tatsächlich kreuzen (Wertegitter: waagrecht bündig, senkrecht knapp).
%
% `padx` setzt den Abstand von Inhalt UND Titel zur Kante — es ist eine Kante
% und deshalb ein Wert (Begründung bei zsftitlebar oben). Für zwei der drei
% Werte steht deshalb NUR `left`/`right` da: Das sind Sammelschlüssel von
% tcolorbox (`left={lefttitle=#1, leftupper=#1, leftlower=#1}`), der Titel
% folgt also von selbst. Ihn danebenzuschreiben wäre derselbe Wert zweimal —
% und beim nächsten Eingriff einmal anders.
%
% `padx=none` ist der Fall, in dem Titel und Inhalt auseinandergehen MÜSSEN,
% und deshalb der einzige, der beide nennt: Die Box polstert nicht, weil ihr
% Inhalt es selbst tut — tablebox und valuegrid lassen ihre Farbfläche bis an
% den Rahmen laufen und halten den Rand in der äussersten Zelle
% (\ZSFtableEdgePad, siehe 20_tables). Der Titel hat keine Zelle und muss den
% Wert direkt lesen; ohne diese Zeile stünde er als einziges Element der Box
% an der blanken Kante.
\tcbset{
  padx/.is choice,
  padx/normal/.style={left=\ZSFboxPadX,    right=\ZSFboxPadX},
  padx/bar/.style   ={left=\ZSFboxPadXBar, right=\ZSFboxPadX},
  padx/none/.style  ={left=0pt,            right=0pt,
                      lefttitle=\ZSFtableEdgePad, righttitle=\ZSFtableEdgePad},
  pady/.is choice,
  pady/normal/.style={top=\ZSFboxPadY,    bottom=\ZSFboxPadY},
  pady/tight/.style ={top=\ZSFtextMinPad, bottom=\ZSFtextMinPad},
  pady/none/.style  ={top=0pt,            bottom=0pt},
}

% Das Gegenstück zu `padx` eine Ebene tiefer: EIN Block statt der ganzen Box.
%
% `padx` gilt für den gesamten Boxinhalt — richtig, solange eine Box eine Art
% Inhalt trägt. Eine `tablebox` trägt aber zwei: die Tabelle, die bis an die
% Kante laufen MUSS (sonst endet das Zebra kurz vor dem Rahmen), und
% gelegentlich einen Satz Prosa darüber, der genau das nicht soll. Mit einem
% Regler pro Box ist einer der beiden zwangsläufig falsch; bisher blieb dafür
% nur ein handgesetztes \leftskip im Kapitel — also genau der lokale
% Notausgang, den das System vermeiden will (rules/02_ai_mandate).
%
% Kein Argument, weil es nur einen sinnvollen Wert gibt: den normalen
% Innenabstand der Box. Ein Regler drückt eine Wahl aus, die der Autor pro
% Stelle trifft — hier gibt es keine (styles/README → Reglertest).
%
% \advance statt \setlength, damit Verschachtelung addiert statt überschreibt;
% die Umgebung bildet eine TeX-Gruppe und stellt beides selbst zurück.
\newenvironment{ZSFinset}{%
  \par\advance\leftskip\ZSFboxPadX\advance\rightskip\ZSFboxPadX
}{%
  \par
}

\newcommand{\ZSFBoxAlign}{}

\newcommand{\ZSFBoxContext}{}

% Rahmen — der Regler wählt die STÄRKE, die Farbe dazu kommt aus dem Ton.
%
% Der Regler setzt `colframe` NICHT selbst, sondern merkt sich nur die Wahl;
% aufgelöst wird sie als letzte Option jeder Box (ZSF@resolveframe, unten an
% der Fabrik). Das ist keine Umständlichkeit, sondern die einzige Form, in der
% der Regler verlässlich ist: tcolorbox löst `colframe` beim Setzen der Option
% sofort per \colorlet auf. Wer den Rahmen früh in der Liste festlegt, verliert
% ihn deshalb an jede spätere Option, die ebenfalls `colframe` schreibt — und
% ein Ton schreibt es. Ein `\begin{goalbox}[T][tone=warn]` bekäme so weder den

% (rules/02_ai_mandate → Randverhalten I).

% Verzögert ist die Reihenfolge dagegen bedeutungslos: Stärke und Ton stehen
% beide fest, wenn der Resolver läuft, egal wer sie gesetzt hat.

% mit. Ein erneutes `boxrule=` NACH dem Basisstil holt damit die Linie unter
% dem Titelbalken zurück, die zsfboxshape gerade auf 0pt gesetzt hat — die Box
% wird um die Linienstärke höher, ohne dass am Rahmen etwas sichtbar wäre.

% bestimmt. Wer Rahmenstärke, Ecken oder Innenabstand des Systems ändern will,

%

% Farbton einer Box — der Regler, der neue Box-Varianten überflüssig macht
% (rules/02_ai_mandate → Katalog-Ökonomie). Jede Box nimmt ihn als Option
% entgegen: \begin{defbox}[Titel][tone=neutral].
%   chapter  folgt der Kapitelfarbe (Default)
%   neutral  kapitelunabhängig grau — für Boxen, die bewusst NICHT zum
%            Kapitel gehören (Meta-Hinweise, Konventionen, Legenden)
%   warn     rote Kopfzeile (die warnbox verwendet genau diesen Ton)
%
% Der Ton hat vier Wirkungen, nicht drei: Fläche, Rahmen, Kopfzeile — und den
% Akzent. Den Akzent trägt eine rahmenlose Box anstelle der Kopfzeile (linker
% Balken und Titelzeile der leisen Box, Aufzählungszeichen der ZSFlist).
% Er gehört in dieselbe Auswahl, sonst bedeutet derselbe Regler auf zwei Boxen
% zweierlei: `tone=neutral` färbte die Fläche grau, liess den Balken aber
% kapitelfarben — halb umgesetzt, ohne dass etwas meldet.
%
% Die beiden Box-Familien nehmen den Ton an verschiedenen Stellen entgegen:
% eine Titelbox über Fläche und Kopfzeile, eine rahmenlose über Akzent und
% ruhige Fläche. Deshalb setzt jeder Ton BEIDE Landepunkte; welchen eine Box
% liest, entscheidet ihr Stil. Das ist der Grund, warum ein einziger Regler
% genügt und die leise Box trotzdem im Kapitelton ungetönt bleibt.
%
% Alle Landepunkte werden per /utils/exec als Makro gesetzt und sind damit auf
% die Optionen-Gruppe der Box beschränkt; die Farbtokens selbst stehen in
% 40_colors_structure (rules/10_architecture → keine Farbtints hier).
%
% Auch die Rahmenfarben sind reine Makros: Der Ton legt sie ab, aufgelöst
% werden sie erst vom Rahmen-Resolver am Ende der Optionsliste. Dadurch ist es
% gleichgültig, ob der Ton vor oder nach der Rahmenwahl steht.
%
% Auch die FLÄCHEN legt der Ton nur als Makros ab — alle drei Rollen, laut,
% ruhig und betont. Welche davon gilt, entscheidet der Flächen-Resolver oben
% aus der Rolle des Bausteins und dem Gewicht. Der Ton schreibt `colback`
% deshalb nie selbst; täte er es, gehörte die Fläche wieder dem letzten
% Schreiber und ein Preset könnte sie nicht mehr vorbelegen.
%
% Der Titelbalken ist die einzige Farbe, die der Ton direkt setzt: Er hat
% keine Rollen, sondern gehört immer dem Ton.
%
% Die Töne selbst stehen in 40_colors_structure — sie sind Farbentscheidungen,
% und dort steht auch \ZSFDeclareTone, das aus einer Deklaration den Schlüssel
% `tone=<Name>` erzeugt. Hier bleibt nichts zu tun: Ein neuer Ton ist eine
% Deklaration und braucht in dieser Datei keine Zeile.

% Schicht 3 — Titelbox. Der EINZIGE Vertrag für Boxen mit Titelbalken; alle
% Presets unten stehen darauf.
%
% Dass hier nur noch zwei Zeilen stehen, ist der Punkt: Form kommt aus
% zsfboxshape, alles Übrige aus dem Vertrag darüber. Eine Titelbox ist damit
% genau das, was ihr Name sagt — eine Box mit Titelbalken.
\tcbset{zsftitlebox/.style={
  zsfboxshape,
  zsftitlebar,
}}

% ------------------------------------------------------------
% Titelbox-Fabrik — ein Aufrufmuster für ALLE Boxen
% ------------------------------------------------------------
% Einheitlicher Aufruf (rules/20_boxes → Aufruf-Konvention):
%   \begin{<box>}[<Titel>][<tcolorbox-Optionen>]
%
% Leerer Titel ⇒ keine Kopfzeile. Ohne diese Fallunterscheidung zeichnet
% tcolorbox bei title={} einen leeren Balken, und jede Box bräuchte eine
% titellose Zweitfassung.
\makeatletter
% Die Fallunterscheidung sitzt in einem tcolorbox-Schlüssel, nicht um das
% \begin herum: So gibt es genau EIN \begin{tcolorbox} und genau ein \end —
% sonst zählt chktex sie gegeneinander auf und meldet sie bis zum Dateiende
% als unbalanciert (Warnung 15, dort nicht mehr lokal unterdrückbar).
\tcbset{zsftitle/.code={\IfBlankTF{#1}{\tcbset{notitle}}{\tcbset{title={#1}}}}}
% Der Titel wird zusätzlich gemerkt, weil `weight=quiet` die Kopfzeile
% abschaltet und ihn stattdessen als erste Inhaltszeile setzt. Das gehört in
% die Fabrik und nicht in eine einzelne Umgebung: Stand es nur in der defbox,
% dann verschluckte `weight=quiet` auf jeder anderen Box den Titel stillschweigend
% — die Kopfzeile war abgeschaltet, die Ersatzzeile fand nichts zu setzen.
% Ein Regler, der auf einer Box Inhalt verliert, ist schlimmer als einer, der
% dort gar nicht gilt (rules/02_ai_mandate → gleiche Sache, gleiche Bedienung).
%
% ZSF@resolveframe und ZSF@resolvesurface stehen bewusst als LETZTE Optionen:
% erst danach sind Rahmen und Fläche aus Rolle bzw. Stärke und Ton
% zusammengesetzt, unabhängig davon, in welcher Reihenfolge Preset und
% Aufrufer sie gewählt haben.
%
% Vor-Lauf für das Gewicht. `weight` ist der einzige Regler, der keinen WERT
% wählt, sondern den BASISSTIL — und ein Basisstil bringt Vorbelegungen mit.
% Stünde er wie die übrigen Regler in der Aufrufer-Liste, liefen seine
% Vorbelegungen nach den Wahlen des Aufrufers und überschrieben sie. Genau das
% war der Fall: `[tone=warn, weight=quiet]` verlor den Ton, `[frame=strong,
% weight=quiet]` den Rahmen — stumm, weil beide Werte für sich gültig sind.
%
% Deshalb wird die Wahl hier vorab aus der Liste gelesen und die fertige Basis
% VOR die Aufrufer-Optionen gesetzt. Danach gilt für jeden Regler dieselbe
% Reihenfolge: Vorbelegung, dann Aufrufer. Dasselbe Muster liest \ZSFfig schon
% für `width`/`height` aus seiner Optionsliste.
%
% .unknown verwirft hier alles andere — es wird gleich darauf in der echten
% Optionsliste ausgewertet. Absolute Schlüsselpfade (/utils/exec) umgehen die
% Familie und laufen im Vor-Lauf mit; in Kapiteln kommen sie nicht vor, und der
% Linter meldet rohe tcolorbox-Eingriffe ohnehin.
%
% Derselbe Vor-Lauf ist zugleich die einzige Stelle, an der die Aufrufer-Liste
% als Ganzes sichtbar ist — und damit der Ort, an dem die Schlüssel abgefangen
% werden, die das System selbst besetzt (siehe \ZSF@ownedKeyError unten).
\newcommand{\ZSF@ownedKeyError}[2]{%
  \PackageError{ZSF}{%
    Schluessel '#1' gehoert dem Box-System, nicht dem Aufruf%
  }{%
    Flaeche und Rahmen werden am Ende jeder Optionsliste aus Rolle und Ton
    zusammengesetzt (ZSF@resolveframe / ZSF@resolvesurface). Ein '#1' im
    Aufruf wird dabei ueberschrieben und bliebe wirkungslos -- frueher
    stillschweigend, jetzt hier. Stattdessen den Regler '#2' verwenden;
    fehlt dafuer ein Wert, ist das eine Luecke und gehoert gemeldet
    (rules/02_ai_mandate -> Randverhalten I).%
  }%
}

  }%

% ------------------------------------------------------------
% Presets — jede Box ist eine Liste aus den Reglern oben
% ------------------------------------------------------------
% Prüffrage an jedes Preset: Steht hier ein Schlüssel, für den es einen Regler
% gäbe? Dann gehört der Regler hin. Rohe Schlüssel bleiben nur, wo die

% ------------------------------------------------------------
% Die Boxgruppe — die Ebene ZWISCHEN Kapitel und Box
% ------------------------------------------------------------
% Bis hierher kannte das System genau einen Geltungsbereich: EINE Box, EINE
% Eigenschaft. Alles, was mehrere Boxen gemeinsam betrifft, hatte deshalb
% keinen Ort — und das ist keine Randfrage, sondern ein häufiges Muster:
% ein Symbol- oder Einheitenregister, dessen Blöcke je einem Kapitel gehören,
% liest sich als EINE durchgehende Tabelle. Ohne diese Ebene entstehen daraus
% n einzelne Boxen mit n wiederholten Kopfzeilen und n Zwischenräumen.
%
%   \begin{ZSFboxgroup}[cols={Y{0.7} Y{1.6} Y{0.7}},
%                       head={\ZSFhead{Symbol} & \ZSFhead{Bedeutung}
%                             & \ZSFhead{Einheit}}]
%     \begin{tablebox}[1. Elektrisches Feld]
%       \begin{ZSFtable}[header=false]{\ZSFgroupcols} … \end{ZSFtable}
%     \end{tablebox}
%     \begin{tablebox}[2. Potenzial] … \end{tablebox}
%   \end{ZSFboxgroup}
%
% Zwei Regler:
%   cols  die gemeinsame Spaltenaufteilung. Steht EINMAL an der Gruppe und
%         wird von den Mitgliedern als \ZSFgroupcols gelesen — sonst stünde
%         dieselbe Aufteilung an jedem Block, und beim n-ten einmal anders.
%   head  die gemeinsame Kopfzeile. Weggelassen ⇒ die Gruppe schliesst nur
%         die Zwischenräume.
%
% DIE KOPFZEILE IST SELBST EINE tablebox MIT EINER ZSFtable. Das ist der
% Kern und nicht ein Implementierungsdetail: Ein eigener Balkentyp müsste
% Rahmenstärke, Innenabstand und Kantenpolsterung der Tabelle NACHBILDEN, und
% beim nächsten Eingriff an einer der beiden Geometrien stünden die Bandspalten
% neben den Tabellenspalten — sichtbar, aber von keinem Test greifbar. Über
% denselben Baustein gebaut ist die Ausrichtung keine Zusage, sondern eine
% Folge (rules/10_architecture → Gestaltung an genau einem Ort).
%
% Die Gruppe trägt ihren eigenen Aussenabstand und nimmt ihn den Mitgliedern:
% innen null, aussen genau einmal der normale Boxabstand.
\makeatletter
\newcommand{\ZSFgroupcols}{}
\newcommand{\ZSF@groupHead}{}
\newlength{\ZSF@groupOuterAfter}
% `font` steht aus demselben Grund an der Gruppe wie `cols`: Es ist eine
% Eigenschaft des BLOCKS und nicht der einzelnen Tabelle. In jedem Mitglied
% wiederholt, steht es beim n-ten einmal anders — und die Kopfzeile erreichte
% es gar nicht, weil sie kein Mitglied ist, sondern die Gruppe sie baut
% (rules/20_boxes → Die Spaltenaufteilung steht an der Gruppe).
%
% Es setzt die VORBELEGUNG (\ZSF@tblFontDefault, 20_tables), nicht das
% Ergebnis: Ein Mitglied mit eigenem `font=` sticht sie weiterhin.
\pgfkeys{
  /zsf/boxgroup/.is family, /zsf/boxgroup,
  cols/.store in=\ZSFgroupcols,
  head/.store in=\ZSF@groupHead,
  font/.is choice,
  font/normal/.code={\renewcommand{\ZSF@tblFontDefault}{\ZSFfontContent}},
  font/dense/.code ={\renewcommand{\ZSF@tblFontDefault}{\ZSFfontContentDense}},
  ZSF@groupDefaults/.style={cols=, head=, font=normal},
}

  \ifZSF@listOrdered\end{enumerate}\else\end{itemize}\fi % chktex 9

% `ordered` und `tone` wirken trotzdem, weil die Liste beide selbst liest
% (Nummerierung; Farbe des Aufzählungszeichens). Jeder andere Regler hat hier
% nichts, worauf er wirken könnte, und verschwand bisher stumm: `\tcbset`
% nahm ihn entgegen, und niemand las ihn je wieder.
%
% Er wird deshalb gemeldet statt geschluckt. Ein Regler, der auf einer Box
% wirkungslos ist, ohne dass etwas sagt, ist die teuerste Fehlerart des

    \PackageError{ZSF}{%
      Regler '\pgfkeyscurrentname' ist auf einer ZSFlist ohne Titel wirkungslos%

      Entweder einen Titel setzen (dann gelten alle Box-Regler) oder die
      Option weglassen. In dieser Form gelten nur: ordered, tone.%
    }%
  },
}

  {\ZSF@listOrderedfalse

  {\ZSF@listClose\ifZSF@listBoxed\end{defbox}\fi} % chktex 9
\makeatother

% \ZSFDerivationCase{Bedingung}{Ausdruck}{Resultat} — Fall über mehrere
% Zeilen; die Sternform setzt denselben Fall einzeilig. Zwei Schreibweisen
